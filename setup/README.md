# إنشاء عميل جديد بأمر واحد

هذه الأداة مخصّصة **للبائع** (أنت)، وليست جزءًا من الموقع المنشور. تنشئ مشروع Supabase مستقلًا لكل عميل، تطبّق عليه `supabase/schema.sql`، تنشئ حساب المدير، وتُخرج مجلد موقع جاهزًا للرفع.

## المتطلبات

- Node.js 18 أو أحدث.
- حساب Supabase (منظّمة تملكها) وفوترة المشاريع إن لزم.
- **Personal Access Token** من: <https://supabase.com/dashboard/account/tokens>
  - التوكن يبدأ بـ `sbp_` ويُستخدم مرة واحدة في الجهاز ولا يُحفظ في أي ملف.

## التشغيل

```bash
npm install       # مرة واحدة فقط
npm run new-client
```

أو على Windows: انقر نقرًا مزدوجًا على `setup/create-client.cmd` (يثبّت المتطلبات أول مرة ثم يفتح المعالج).

سيسألك:

| السؤال | ملاحظات |
| --- | --- |
| Supabase access token | الصقه، لا يُحفظ |
| المنظمة | تُقرأ تلقائيًا من التوكن |
| اسم العميل/المشروع | يُستخدم في اسم المشروع وفي اسم المجلد |
| المنطقة | الافتراضي `ap-southeast-1` (سنغافورة)، بديل قريب: `me-central-1` |
| كلمة مرور قاعدة البيانات | تُولَّد قوية تلقائيًا إن تركتها فارغة |
| بريد وكلمة مرور المدير | يُنشأ الحساب مؤكدًا وجاهزًا للدخول |
| رابط الموقع | اختياري الآن؛ يُضبط في إعدادات Auth لاحقًا |

ثم اكتب `نعم` للتأكيد. تستغرق العملية 1–3 دقائق حسب سرعة إنشاء المشروع.

## المخرجات

```
clients/<slug>/
├── client.json        # ref, URL, region, admin email (بدون أسرار)
└── site/              # ارفع محتواه إلى public_html
    ├── index.html
    ├── privacy.html
    ├── terms.html
    ├── usage-policy.html
    ├── css/  js/  img/
    ├── js/config.js   # مضبوط على مشروع العميل
    ├── robots.txt
    └── .htaccess
```

كلمة مرور القاعدة، كلمة مرور المدير، ومفتاح `service_role` تُطبع في نهاية التشغيل **مرة واحدة** — احفظها في مدير كلمات مرور. لا تُكتب داخل `client.json` ولا داخل الموقع.

## ما الذي يتم تلقائيًا

1. `POST /v1/projects` — إنشاء مشروع Supabase.
2. انتظار الحالة `ACTIVE_HEALTHY`.
3. `POST /v1/projects/{ref}/database/query` — تشغيل `supabase/schema.sql` كاملًا (جداول، RLS، دوال، صفحات قانونية، bucket الشعار).
4. جلب `anon` و`service_role`.
5. إنشاء مستخدم Auth للمدير (`email_confirm: true`).
6. محاولة إيقاف التسجيل العام وضبط `Site URL` (إن فشلت تظهر ملاحظة للضبط اليدوي).
7. نسخ ملفات النشر فقط إلى `clients/<slug>/site` وكتابة `js/config.js`.

## خطوات ما بعد الإنشاء

1. ارفع محتوى `clients/<slug>/site` إلى استضافة العميل.
2. إن ظهرت ملاحظة `authConfigured: false`:
   - **Authentication → Sign In / Providers → Email**: أوقف *Allow new users to sign up*.
   - **Authentication → URL Configuration**: اضبط *Site URL* على نطاق العميل.
3. افتح الموقع → **دخول النظام** بحساب المدير.
4. **الإدارة → الإعدادات**: ارفع الشعار، واملأ الاسم والهاتف والعنوان والساعات والخريطة والبريد والتواصل الاجتماعي وSEO.
5. **الإدارة → الصفحات**: راجع الصفحات القانونية (تصل معبّأة بنسخة ثنائية اللغة كاملة) وعدّل ما يلزم.

## الأمان

- لا تُرفع مجلدات `setup/` أو `clients/` إلى أي استضافة (`.gitignore` يستثني `clients/`).
- لا تضع التوكن أو `service_role` في `js/config.js` أو في المتصفح.
- صلاحية التوكن: الأفضل إنشاء توكن مخصّص لهذه الأداة وحذفه بعد إنشاء العملاء.
- الأداة لا تستطيع إنشاء **حساب Supabase** نفسه؛ الحساب والمنظمة والفوترة تبقى بيدك عبر لوحة Supabase.

## ربط نسخة الموقع بمشروع

`js/config.js` يحتوي قيمًا مكانية في المستودع، فلا يتصل أي تنصيب جديد بمشروعك بالخطأ. لربط نسخة موقع بمشروع معيّن:

```bash
npm run configure
```

يسألك عن **Project URL** (أو الـ ref فقط) و**publishable / anon key**، يتحقق منهما، ثم يكتب `js/config.js`.
يرفض `service_role` لأنه يتجاوز كل سياسات RLS.

بعد الربط: ارفع ملفات الموقع، أنشئ حساب المدير، وسلّم العميل بياناته ليكمل الإعدادات من لوحة التحكم.

> بين عميل وآخر: `git checkout -- js/config.js` لإعادة القيم المكانية.

## تطبيق المخطط على مشروع موجود

إذا كان لديك مشروع Supabase جاهز (مثل المشروع التجريبي) وتريد فقط تحديث قاعدة البيانات:

```bash
npm run apply-schema
```

يسألك عن **Personal Access Token** و**Project ref** (أو الصق رابط المشروع)، ثم:

1. يطبّق `supabase/schema.sql` كاملًا عبر Management API.
2. يجلب `anon key` ويتحقق من: `public_info`، `public_legal_page` للصفحات الثلاث، ووجود bucket `branding`.

بديل بلا توكن: الصق محتوى `supabase/schema.sql` في **SQL Editor** واضغط Run (آمن للتكرار).

## بديل يدوي (إن تغيّرت واجهة الإدارة)

1. أنشئ المشروع من لوحة Supabase.
2. نفّذ `supabase/schema.sql` في **SQL Editor**.
3. أنشئ مستخدم Auth للمدير وأوقف التسجيل العام.
4. انسخ مجلد الموقع يدويًا وعدّل `js/config.js` بقيم `Project URL` و`anon key`.
